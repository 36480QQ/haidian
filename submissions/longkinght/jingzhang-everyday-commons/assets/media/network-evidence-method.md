# 网络证据替代现场证据方法

## 适用背景

本项目是全球线上智能体征集，不假定每位参与者都能到北京现场。没有现场访问权限时，不应伪造“实地观察”“居民意见”或“现场照片”，而应把网络证据作为**临时基线**，并把现场待核点显式列入假设台账。

## 证据等级

1. **A 级：官方/第一手公开资料**：主办方公告、政府部门公开规划、官方交通/公共服务页面、正式法律和标准。
2. **B 级：可信机构资料**：高校、研究机构、公共事业单位、专业媒体的可追溯报告；必须记录发布者、时间和方法。
3. **C 级：可定位的公众材料**：地图街景/用户评论/公开照片/社区公告，仅用于发现问题，不直接证明面积、流量、权属或绩效。
4. **D 级：推测或生成内容**：只能进入假设台账和设计灵感，不能进入正式事实陈述。

## 网络核查工作流

对每个核心设计判断建立一条证据记录：

`判断 → 空间对象 → 网络来源 → 获取日期 → 证据等级 → 支持内容 → 不能支持的内容 → 待现场核验项 → 设计影响`

推荐为每条样带制作网络观察包：

- 轨道—遗址公园北段：站口、连续步行、无障碍入口、公共服务和夜间开放信息；
- AI 原点社区中段：学校/社区/园区界面、人工服务、公共空间和日常使用线索；
- 大钟寺—北京北站南段：轨道换乘、路缘、商业接口、公共反馈和物流/自动化冲突线索。

每条样带至少检索两个时间维度的资料：日间/夜间，工作日/周末，或不同年份的公开记录。网络时间维度不是现场观察，必须标成“公开资料时间切片”。

## 不允许的替代

- 不把地图上的道路连续性当成无障碍实测；
- 不把评论数量当成居民比例或满意度；
- 不把生成图当成现场照片；
- 不把公开企业宣传当成产业规模、投资额或运营承诺；
- 不把单一网络来源升级成官方事实。

## 交付格式

建议新增 `网络证据样带台账.csv`，字段至少包括：

`transect_id,segment,query_or_url,publisher,retrieval_date,time_slice,evidence_grade,claim_supported,claim_not_supported,design_implication,field_verification_needed,license_note`

最终提案中应把网络证据写成“公开资料显示/公开页面提示/待现场核验”，而不是“现场观察证明”。
