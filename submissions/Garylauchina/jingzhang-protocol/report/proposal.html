V0.6 核心命题

本方案不把“AI 城市”理解为设备、屏幕和演示项目的叠加。正式项目名仍是 京张协议 / THE JING-ZHANG PROTOCOL，指后台的城市公共协议系统；公众走进街区时接触到的前台概念则是 京张回程票 / THE RETURN TICKET。每项 AI 能力在进入日常服务前，都应让人看懂它从哪里来、为何使用数据、能做与不能做什么、由谁接管、如何申诉、能否迁移，以及何时暂停或退出。它不是一张准入证，而是一份可带走、可追问、可触发返还的公共回执：能力没有回程，不得进入日常城市服务。 所有制度、空间与运营内容均为概念建议，仍需规划、工程、法律、伦理和公众参与等专业程序深化 来源 标准。

京张铁路的历史价值不只是一条可借用的“轨道”意象。国家铁路局将 1905—1909 年建设的京张铁路界定为中国人自己勘测、设计、施工和管理的第一条国有干线铁路；北京市现有遗址公园则通过恢复老正线、保留清华园站房和缝合铁路两侧空间，让工程遗产继续成为开放公共生活的一部分 来源 来源。方案据此提出一种明确的当代转译：铁路时代把自主工程能力写入地理，AI 时代则要把可问责、可互操作、可修订的机器智能写入社会。后一句是设计论题，不是史料原句。

空间上，方案以 BUILD → TEST → LIVE → LEARN / UPDATE 作为“三区两翼”之上的运行生命周期：众智园侧重 BUILD，北京 AI 原点社区侧重 TEST，大钟寺侧重 LIVE，中关村科技服务翼与小月河场景赋能翼共同支撑跨区服务、公共体验和证据回流，全带通过 LEARN / UPDATE 形成版本化的治理闭环。“回程票”沿既有七接口城市服务链移动，把能力发布、受控试验、日常使用、暂停退出与规则修订串成同一条公众可读的责任路径；它不新增法定分区，也不替代官方任务书的三层范围与三区两翼结构 空间数据 空间数据 深度。

后台采用两层架构：AI City API / Jing-Zhang AI Civic Protocol 是联邦式的机器与运营互操作契约，不是单一中心平台或项目准入闸门；Jing-Zhang AI Constitution / 京张 AI 城市公约 是由场景讨论、公众参与、专业审查和运行证据共同修订的版本化公约。前者规定系统怎样交换最低必要信息，后者规定谁有权修改规则、公众拥有哪些权利、证据与申诉如何进入公共记忆；“回程票”则把两层要求翻译成公众可见的回执。七类最低接口为：①身份与来源；②数据目的与保存期限；③能力与限制；④人工权责与非数字替代；⑤申诉与补救；⑥互操作与可迁移；⑦版本、暂停、退出与公共记忆 指标。三者均不是已建平台、法定许可、已生效法律或政府审批流程。

城市能力返还机制

“返还”不是把城市数据或公共权力让渡给技术提供者，而是在期限届满、重大版本变化、证据不达标、申诉久未解决、运营方退出，或权利/数据/工程条件失效时，把服务能力安全地交还给公众与城市运营体系。V0.6 已登记 BUILD、TEST、LIVE 三个能力返还节点，数量为 3 指标；它们分别承担开放方法与失败证据、无应用服务与可达性修复、申诉补救与公共记忆返还 空间数据 空间数据 空间数据。12 个要求回程票的应用场景均可反向解析到相应返还节点，引用覆盖率为 1.0；这证明机器引用闭合，不证明能力已经交付 指标。三个节点均为 concept_only 点位索引，不是既有机构、运营主体或建设承诺。
