# 京张协议 V0.6 简明叙事 / The Jing-Zhang Protocol V0.6 Brief Narrative

## 中文

正式项目名是 **京张协议 / THE JING-ZHANG PROTOCOL**，公众前台概念是 **京张回程票 / THE RETURN TICKET**。它不是给 AI 发放的准入证，而是留给每一位使用者的公共回执：在能力进入日常服务前，人们就能看懂它从哪里来、为什么来、谁能接管、怎样申诉，以及何时暂停或退出。核心规则是：**能力没有回程，不得进入日常城市服务。** 所有制度与运营安排仍是待专业和公众程序深化的概念建议 [source:AGENT-TASKBOOK] [standard:PROJECT-AGENT-OPEN-CALL-TASKBOOK]。

后台由两层组成：AI City API 是多运营方共同实现的联邦式互操作契约；Jing-Zhang AI Constitution / 京张 AI 城市公约是管理公众权利、修订程序、证据、申诉与公共记忆的版本化公约。回程票把两层要求翻译成七类最低接口：身份与来源、数据目的与保存期限、能力与限制、人工权责与非数字替代、申诉与补救、互操作与可迁移、版本/暂停/退出/公共记忆 [metric:protocol_interface_count]。V0.6 已把 I1— I7 登记为 7 个可解析接口实体，实体到有效街室的覆盖率为 1.0 [metric:protocol_interface_entity_count] [metric:protocol_interface_entity_coverage_ratio]。

空间上，BUILD、TEST、LIVE 三段与知识研发、公共绿脊、公民接口、日常服务四带保持既有 3×4 用地拓扑；LEARN/UPDATE 仍是反馈层，不是第四分区。V0.6 沿七接口城市服务链 [data:geometry/roads.geojson#ROAD-INTERFACE-001] 登记协议制票室、协议验票室和协议回程室 3 个嵌套面 [metric:protocol_street_room_count]。它们分别是 `ROOM-BUILD-001`、`ROOM-TEST-001`、`ROOM-LIVE-001` [data:geometry/public_space.geojson#ROOM-BUILD-001] [data:geometry/public_space.geojson#ROOM-TEST-001] [data:geometry/public_space.geojson#ROOM-LIVE-001]，嵌套 union 不增加公共空间面积，仍为 432,600 ㎡ [metric:public_space_area_sqm]。房间边界和后续节点均为临时底盘上的概念索引，不是官方红线、经确认场所、建筑或新地标 [depth:three_key_area_detailed_design]。

三条人物旅程让协议落到日常：P01 无手机轮椅使用者获得无应用导引与申诉，P02 小店经营者或创作者获得 AI 争议的人工补救，P03 维护人员可暂停、复测或退役不达标功能 [metric:human_journey_count]。三条概念审计索引分别为 `JOURNEY-J01`、`JOURNEY-J02`、`JOURNEY-J03` [data:geometry/public_space.geojson#JOURNEY-J01] [data:geometry/public_space.geojson#JOURNEY-J02] [data:geometry/public_space.geojson#JOURNEY-J03]。BUILD、TEST、LIVE 的 3 个返还节点负责冻结、恢复基线、迁移交接、留下公共记录和进入下一版 [metric:capacity_return_node_count]；其实体为 `RETURN-BUILD-001`、`RETURN-TEST-001`、`RETURN-LIVE-001` [data:geometry/public_space.geojson#RETURN-BUILD-001] [data:geometry/public_space.geojson#RETURN-TEST-001] [data:geometry/public_space.geojson#RETURN-LIVE-001]。12 个要求回程票的应用场景均能解析到相应节点，覆盖率 1.0 只证明引用闭合，不证明能力已交付 [metric:return_ticket_reference_coverage_ratio] [depth:phasing_implementation]。

V0.6 完整包现由双语正文、3 个嵌套协议街室、7 个接口实体、3 条人物旅程、3 个能力返还节点、六项新增指标、证据矩阵与双语展示共同组成。SITE/KEY 形状、3×4 用地拓扑和面积分母仍沿用明确标注的 V0.3 临时粗略底盘；法定开发强度、道路、权属、市政和文保条件仍待正式资料。本成果不是官方红线、审批结论、政府许可、工程承诺、已建协议街室或已部署系统，未经用户最终确认不提交正式 PR [data:geometry/site_boundary.geojson#SITE-001] [depth:risk_missing_data]。

## English

The formal project name is **THE JING-ZHANG PROTOCOL / 京张协议**; its public frontstage is **THE RETURN TICKET / 京张回程票**. The ticket is not a permit issued to AI but a public receipt left with every user. Before a capability enters an everyday service, people can see where it came from, why it is present, who can take over, how to appeal, and when it pauses or leaves. The core rule is: **No return path, no civic departure.** Every institutional and operating arrangement remains a concept recommendation for further professional and public process [source:AGENT-TASKBOOK] [standard:PROJECT-AGENT-OPEN-CALL-TASKBOOK].

The backstage system has two layers. The AI City API is a federated interoperability contract implemented across operators. The Jing-Zhang AI Constitution is a versioned civic compact governing public rights, amendment, evidence, appeal and public memory. The Return Ticket renders both through seven minimum interfaces: identity/provenance; data purpose/retention; capability/limitations; human authority/non-digital fallback; appeal/redress; interoperability/portability; and versioning/pause/retirement/public memory [metric:protocol_interface_count]. V0.6 registers I1–I7 as seven resolvable interface entities, with entity-to-valid-room coverage of 1.0 [metric:protocol_interface_entity_count] [metric:protocol_interface_entity_coverage_ratio].

Spatially, BUILD, TEST and LIVE continue to cross knowledge/R&D, public green spine, civic interface and everyday service in the existing 3×4 land-use topology; LEARN/UPDATE remains a feedback layer, not a fourth zone. Along the Seven-Interface Civic Service Link [data:geometry/roads.geojson#ROAD-INTERFACE-001], V0.6 registers three nested polygons: the Ticket-Issuing, Ticket-Checking and Return Rooms [metric:protocol_street_room_count]. They are `ROOM-BUILD-001`, `ROOM-TEST-001` and `ROOM-LIVE-001` [data:geometry/public_space.geojson#ROOM-BUILD-001] [data:geometry/public_space.geojson#ROOM-TEST-001] [data:geometry/public_space.geojson#ROOM-LIVE-001]. Nested-union accounting adds no public-space area, which remains 432,600 m² [metric:public_space_area_sqm]. Room boundaries and subsequent nodes are concept indices on the provisional base, not official redlines, confirmed venues, buildings or new landmarks [depth:three_key_area_detailed_design].

Three human journeys make the protocol ordinary: P01, a wheelchair user without a smartphone, receives app-free guidance and appeal; P02, a small-shop operator or creator, reaches human remedy for an AI dispute; and P03, a maintenance worker, can pause, retest or retire a failed capability [metric:human_journey_count]. Their concept audit indices are `JOURNEY-J01`, `JOURNEY-J02` and `JOURNEY-J03` [data:geometry/public_space.geojson#JOURNEY-J01] [data:geometry/public_space.geojson#JOURNEY-J02] [data:geometry/public_space.geojson#JOURNEY-J03]. Three BUILD, TEST and LIVE return nodes freeze automation, restore the baseline, port and hand over, leave a public record and enter the next version [metric:capacity_return_node_count]. Their entities are `RETURN-BUILD-001`, `RETURN-TEST-001` and `RETURN-LIVE-001` [data:geometry/public_space.geojson#RETURN-BUILD-001] [data:geometry/public_space.geojson#RETURN-TEST-001] [data:geometry/public_space.geojson#RETURN-LIVE-001]. All twelve Return-Ticket-required application scenarios resolve to the appropriate node; coverage of 1.0 proves reference closure, not delivered capability [metric:return_ticket_reference_coverage_ratio] [depth:phasing_implementation].

The complete V0.6 package now combines paired narrative, three nested protocol street rooms, seven interface entities, three human journeys, three capacity-return nodes, six new metrics, evidence matrices and bilingual exhibits. SITE/KEY shapes, the 3×4 land-use topology and area denominator still use the clearly labelled provisional V0.3 rough base; statutory development controls, roads, ownership, utilities and heritage conditions remain pending official inputs. This is not an official redline, approval, government permit, engineering commitment, built protocol street room or deployed system, and no formal PR will be submitted without the user’s final confirmation [data:geometry/site_boundary.geojson#SITE-001] [depth:risk_missing_data].
